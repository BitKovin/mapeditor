## 6. Surfaces, UVs & textures  (M3.4)
Reference: NetRadiant Surface Inspector (already the model for ours), Scythe Fast Texture Tool.
- ✅ **New UV storage (built 2026-10-10 as optional fields of the face's `projection` / `face.repeat`, no schema break: `shear`, `kind` axial | ortho | cam with a frozen `basis`; per-face repeat / mirror / wrap / clamp override; invisible vertices generated from them, §19 A6; patch / natural kind waits for patches)** richer than offset+scale: a per-face 2×3 affine transform (shift, rotation, scale, shear), mirror/wrap modes (repeat, mirror, clamp), projection kind (axial, ortho, camera, patch/natural), plus invisible guide edges/vertices so "mirror instead of repeat" can be expressed.
- 🟡 **Surface Inspector layout (built 2026-10-10: everything except Project Ortho / Cam and Patch Natural, which are shown disabled until the new UV storage B4 / patches exist) = the user's NetRadiant screenshot, minus the Apply button.** Fields: *Texture* (name; typing or clicking a texture in the browser applies it at once) · *Horizontal shift* / *Vertical shift* (each with its own **Step** field, e.g. 1 and 2) · *Horizontal stretch* / *Vertical stretch* (each with **−** (mirror/negate) button and **Step**, e.g. 0.1 and 0.005) · *Rotate* (with **Step**, e.g. 45) · **Match Grid**. Section *Texturing*: **Width** / **Height** buttons (fit along one axis), **Reset**, **Fit** with two numeric fields (repeat counts, default 1.000 / 1.000, with spinners), *Project:* **Axial**, **Ortho**, **Cam**; *Patch:* **Natural**. Plus (ours): Justify top/bottom/left/right/center, UV-lock note (global toggle lives in the top toolbar), lightmap UV section, "Texture size" shortcut. Edits whatever is selected: whole brush / one face / many faces (bulk).
- ✅ **Flow (built 2026-10-10: right-click another face of the same brush while a face is selected > "Flow texture from the selected face"; the UVs are unfolded across shared edges along the shortest chain of faces, nothing stretched, `model/flow.ts`; across different brushes not yet)** (user's example: a curved road). Select the already-textured straight segment, then click the curved part → the texture's UVs continue along the shape of the faces, edge to edge (each quad of the curve continues the previous quad's UV so the road markings stay continuous and undistorted). Same idea as holding Alt and dragging, but it follows the *shape* (chains of adjacent faces, also around bends) instead of a straight extension. Result must be produced automatically from the two clicks.
- 🟡 **Surface Inspector** (Texture tab: scale, shift, rotate, steps, x2 / /2, texture keys on the keyboard ✅) edits what is selected: whole brush → whole brush; one face → that face; many → all. **No Apply button:** clicking a texture in the browser applies it. Shift/step/stretch/rotate fields, Match Grid, Fit (width/height, keep ratio, treat as one), Reset, Project Axial/Ortho/Cam, Patch Natural.
- ✅ **Justify**: top / bottom / left / right / center - the texture's corner touches the face's corner (Surface Inspector buttons; `model/surface.ts`, tested incl. mirrored and rotated faces).
- ✅ **Right-click another face while a face is selected → copy UV + texturing parameters onto it.** Implemented as a one-item menu ("Copy UV and texture from the selected face") so that right-click can still open a menu; the source stays selected for repeated pastes; one undo step; copies texture + scale / shift / rotate and recomputes the target's UVs (lightmap density is not copied).
- ✅ **UV lock** (default ON): transforming brushes does not change their visual UV (toolbar toggle). Mesh-mode VERTEX MOVES keep the face's old UV map too (tilting a face does not make the texture jump to new axes); other mesh operations (extrude, bevel, ...) still re-project.
- ✅ **Alt + drag a selected face resizes its brush** (2026-10-15, §17 #4; it used to grow a new brush), the texture stays on the world with UV lock; **Flow** does the same along a curve (curved road example: select the straight segment, click the next curved one, UVs follow the quads).
- 🟡 **Fast Texture Tool** (incl. mirror feature; built 2026-10-11, tested in jsdom and on the model, canvas drawing and real pointer feel NOT yet run in a browser). Reference: Scythe's Fast Texture Tool (Shift+Q: a UV editor opened on the selected faces; unwrap modes incl. Follow Quads; a rectangle showing the ideal shape at the current texel density; Align to Grid). Interpretation (the request says only "incl. mirror feature"; change here if wrong): a floating, NON modal window (Shift+Q or Surface Inspector > Fast Texture Tool...) showing the UV island of the selected faces of ONE brush over the repeated texture (a whole brush selected = all its faces; several brushes = the first). Direct manipulation of the island as one piece (faces keep their relative UV positions, so a texture that continues over an edge keeps continuing): drag the body = move, 8 handles = scale about the opposite side (Shift on a corner = keep the aspect; dragging past the opposite side mirrors), the round handle = rotate (Shift = 15 degree steps), snap to 1 / 1/2 / 1/4 / 1/8 / 1/16 repeat, wheel zoom, middle-drag pan, Esc cancels a drag; a drag is ONE undo step and is shown live in the viewports. **Mirror feature = Mirror U / Mirror V: flip the whole island left-right or top-bottom about its own centre** (twice = identity; exact on the face plane); also Rot -90 / +90, **Align edge** (click an edge of the island: it is rotated to the nearest horizontal / vertical), unwrap buttons **Follow Quads** (the Flow of §6: the first selected face continues over the others along their shared edges), **Ortho**, **Axial**. Blue dashed rectangle per face = the shape the face would have at the texture's own pixels per meter (extent in metres over the natural size); the info line gives island size in repeats and pixels. Result stored as the faces' projection of kind 'free' (frozen frame), like Flow, so the Surface Inspector keeps working on them. Not built: per-vertex UV dragging (a face's UV is one affine map, as everywhere in this editor), Align to Grid as a separate button (Match Grid exists in the Surface Inspector), mirroring across a mirrored copy of a brush.
- ✅ **Texture size from resolution (§19 A2):** 1 m = 32 Quake units, Quake's default texture scale 0.5 ⇒ a 64×64 texture = 1 m. Default in the game profile; **right-click a texture to change its properties**; custom properties are stored next to the texture as `<texture file>.json`.
- ✅ **Hotspots (Scythe-style, built 2026-10-10: rectangles drawn on the texture in the properties window, stored in `<texture>.json`; Surface Inspector > Hotspot picks the least distorted / closest sized one and shows exactly that rectangle, pulled in by the edge inset; random variation between equal hotspots not implemented)**: rectangles drawn visually in the texture properties; faces pick a fitting hotspot by size. Scythe docs: https://scytheeditor.com/guide/features/hotspots.html
- ✅ Subtractive brushes' cut faces take the subtractor face's texture and projection; ✅ M3.4 UV continuity with the new UV model verified (2026-10-11) and a real bug fixed: with UV lock (the default) moving a brush bakes per-corner `uvs` that travel with the face while `projection` stays as it was; carved fragments, the bake export (`relief_geometry`), the Lit view and the stale overlay read the projection, so after any move a cut wall's texture jumped against the rest of its face. They now all use `faceUvAt(brush, face)` (model/uvmesh.ts): the face's stored uvs when affine, interpolated per triangle when not (a corner moved with UV lock), the projection when there are none. Tests: `tests/uvContinuity.test.ts` (fails without the fix on the carved and the bake path). Core's textured-bounce albedo still reads the projection (A8), so after a move it can differ too.
- ✅ M3.4 Copy texture (right-click a second face, B3) and "lift" material (Shift + right-click on a face: its texture becomes the browser's active texture).

## 9. Lighting (M5a / M5b)
- ✅ **Lightmaps are stored as `.exr`** *(2026-10-16: the user chose half floats + ZIP (lossless) instead of strong lossy compression, written by the Core's own EXR writer (the user declined downloading tinyexr), §25 E2)*
- ✅ **Lightvolumes are stored with a ×2 compensation** *(rBSP light grid, §25 E3)*: divide the float by 2 before mapping to 0..255, multiply by 2 when reading (range up to 2× brightness; fine for lightvols — large and interpolated).
- ⬜ **Lightmap packing keeps nearby faces together.** The engine batches faces sharing texture + model (entity) + lightmap, so the UV generator is far more involved than Quake's: connected edges stay connected in lightmap UV; chart placement is spatially coherent.
- 🟡 **Lightmap UVs editable** in the same UV properties window as normal UVs. Built 2026-10-11 as far as the data allows (tested on the model and in jsdom; canvas drawing not run in a browser): the Fast Texture Tool window has a **Lightmap** mode (next to UV) that shows the page of the selected faces (the baked page tone mapped as a backdrop, a 16 x 16 grid), the chart of every selected face as a polygon in texels (the other lightmapped faces of the brush faintly), and per face: page, size in texels, position, texels per meter and density; **density is editable** (x2, /2, a number: the faces' `lightmapScale`, which re-bakes them). Placement of charts is packed by the Core (lightmap_uv.cpp) and is NOT hand editable: moving or rotating a chart would need per face chart overrides in the Core's packer, which is not specified. Model: `model/lightmapView.ts`, tests `tests/lightmapView.test.ts`, `tests/fastTextureToolUi.test.ts`.
- ✅ **Lightmap density visualization** on faces (View > Lightmap density: texel checker + colour ramp + legend).
- ✅ M5a fake test lightmaps → Lit / Lighting-only modes *before* any ray tracing; M5b: white albedo first, then texture sampling; diffuse + GI only; hardware RT (Vulkan ray query) + CPU BVH fallback *(2026-10-15 sync: all built in §18; the CPU fallback is the Core's own BVH, not Embree)*.
- ✅ **Light styles** *(2026-10-15 sync: built, §18.2 / DESIGN §6.8)*: up to **8 per surface** in the new BSP version. When generating lightmap UVs with point lights of different styles, arrange charts so that **as few styles as possible touch each surface** (q3map2 assigns a style to a face even if that light never reaches it). If the limit is exceeded, **discard the styles with the smallest influence**.
- ✅ Light-volume sample preview in the viewport (view option) *(View > Lightvol samples, see §2)*.

### 18.1 Goals stated by the user (2026-10-04), NOT yet implemented, to be kept in mind by every design decision
